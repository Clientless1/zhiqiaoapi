# 套餐与计费

## 两种计费方式

- **额度套餐**：购买即获得独立的调用额度。密钥绑定此套餐后，只消费套餐额度，额度不足不会转扣账户余额。
- **按量计费**：密钥调用时仍从原有余额账户结算。历史收费访问资格保留原来的有效期与续费规则。

存量按量计费模型系列不会自动变成付费额度套餐。管理员在「用户运营 → 套餐」创建新的额度商品，并自行决定售价、额度和模型范围。

## 后台配置

选择「额度套餐」，设置售价、有效天数、模型范围，以及至少一种额度：

| 配置 | 作用 |
| --- | --- |
| 总额度 | 每份套餐在有效期内累计可消费的上限 |
| 每日额度 | 每个北京时间自然日的上限，00:00 重置 |
| 每周额度 | 每个北京时间自然周的上限，周一 00:00 重置 |

未填写的维度不限制；多种上限同时填写时，按剩余额度最少的维度限制消费。额度与模型调用价格使用平台配置的同一计费币种，不代表请求次数或 token 数。

每份商品独立保存购买时的额度和到期时间。修改售价、额度、有效期只影响后续购买。生效期间允许停售，但不允许停止服务或变更模型范围；已有密钥或订阅的商品不允许切换计费方式，可另建商品。

## 用户购买与使用

1. 在「套餐 → 额度套餐」选择商品，用账户余额支付，可选择符合门槛的优惠券。
2. 购买后点击「创建密钥」，系统会预选该套餐。之后可导入 CC Switch 或按平台接入文档手动配置。
3. 「我的套餐」逐份显示剩余总额度、今日额度、本周额度与到期时间。显示余量包含正在调用的预占额度。
4. 每把绑定相同套餐的密钥共享同一用户的套餐权益，不能通过创建多把密钥绕过限额。
5. 重复购买新增一份独立权益。额度叠加，优先使用较早到期的权益，旧权益不会延期；每份到期后停止提供其额度。
6. 兑换套餐的兑换码同样生成独立权益，兑换码不可重复使用。

## 扣费可靠性

购买扣款、优惠券使用、订单与权益在同一数据库事务内提交。购买请求有幂等 ID，重试不会重复扣款或重复发放。

调用前在数据库锁定额度账户并预留预计费用，多把密钥的并发请求不能超卖额度。成功调用通过既有持久化计费队列按实际用量结算；失败调用释放预占。套餐额度继续使用原有账本、租约心跳和重启恢复机制，进程退出不会依赖内存保存套餐消耗。

套餐与余额在账本中分别标识。对于仅设置日/周额度的套餐，账本不展示内部记账容量为现金余额。
